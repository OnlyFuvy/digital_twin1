# Андрей — навигация

## Что сделано и где смотреть

[`dtwin/navigation.py`](../../dtwin/navigation.py), функция `navigate`, реализует бесплатформенную инерциальную навигацию с альфа-бета-коррекцией по GNSS. Входы — измерения IMU1 и GNSS1; выходы — оценённые координаты, ошибки и статистика принятых поправок. Результаты: `results/reference/navigation.csv`, `results/reference/results.json`, график `figures/navigation.png`. Интеграция идёт на частоте IMU — **200 Гц**, GNSS-поправки приходят на **20 Гц**.

## Как работает БИНС

При начальной выставке берутся начальные координаты, скорость и ориентация модельного аппарата. Далее ориентация обновляется по гироскопам, скорость и координаты — по акселерометрам. Истинная траектория после выставки нужна для оценки ошибки и не подмешивается в решение.

Матрица `R` переводит векторы из корпуса FLU в мир ENU. Из удельной силы восстанавливается ускорение:

`aмир = R × fкорп + (0; 0; −9,80665)`.

На шаге интегрирования:

`pнов = pстар + vстар Δt + 0,5 a Δt²`, `vнов = vстар + a Δt`.

Измерения соседних отсчётов IMU предварительно усредняются. Угловое приращение `ωΔt` преобразуется в поворот по формуле Родрига. Каждые 1000 шагов матрица ортонормируется через SVD, чтобы численные ошибки не разрушали свойства поворота.

## Как GNSS сдерживает ошибку

GNSS измеряет положение антенны, а не центра масс. Поэтому сначала вычитается повернутое плечо: `pизмер = pантенны−Rr`. Невязка — разность измеренной и расчётной позиции.

При обычном поступлении GNSS часть невязки добавляется к позиции с коэффициентом **α=0,12**, а часть корректирует скорость: **β=0,002** с делением на интервал между поправками. Это простой комплементарный фильтр, не EKF.

При потере GNSS на 300–360 с поправки пропускаются, остаётся IMU-интегрирование и ошибка растёт. После длительного перерыва первая принятая поправка использует **α=0,8 и β=0**: быстро возвращает позицию, не создавая резкого скачка скорости. Невязки более 5 км отклоняются. Учитываются признаки достоверности GNSS и плечо антенны.

Параллельно ведётся вариант **без GNSS-коррекции** с теми же инерциальными измерениями. Он показывает накопление ошибки. Постоянные смещения и шумы IMU интегрируются: ошибка ускорения превращается в ошибку скорости, затем позиции; ошибка ориентации дополнительно искажает проекцию силы тяжести.

## Результаты и проверки

`navigation.metrics` содержит RMSE, максимальную и конечную ошибки, максимум во время отказа, ошибку чистой БИНС и число принятых/отклонённых поправок. RMSE — корень из среднего квадрата пространственной ошибки. Сравниваются `nominal` и `gnss_dropout`; точные значения берутся из актуальных JSON, чтобы не перепутать версии.

`tests/test_navigation.py` проверяет неподвижный аппарат без шума и равномерное движение без GNSS: решение не должно дрейфовать без причины. Полный эксперимент демонстрирует рост ошибки на отказе и её уменьшение после восстановления внешних измерений.

```bash
python -m dtwin simulate --scenario gnss_dropout --record
python -m dtwin replay results/reference
```

Первая команда пишет в `results/run/` по умолчанию; для просмотра именно нового расчёта используется `python -m dtwin replay results/run`.

## Что сказать на защите

«Я отвечаю за оценку движения по IMU и GNSS. Инерциальная часть работает непрерывно, а спутниковые поправки сдерживают накопление ошибки. На минуту отключаем GNSS и видим рост ошибки; после восстановления позиция снова корректируется. Истинное движение после начальной выставки используется для сравнения, а не для скрытой коррекции».

Ограничения: плоская Земля, постоянное g, простая модель коррекции без оценки смещений IMU. Ошибки навигации не меняют заданную траекторию: замкнутого автопилота нет, резервный GNSS2 не подключён к автоматическому переключению.
