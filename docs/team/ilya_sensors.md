# Илья — датчики

## Что сделано и где смотреть

[`dtwin/sensors.py`](../../dtwin/sensors.py) формирует измерения, [`config/sensors.json`](../../config/sensors.json) задаёт координаты, частоты и размерности; `load_sensors` в [`dtwin/config.py`](../../dtwin/config.py) уточняет частоты по скорости. Выход каждого канала: время, значения, единицы и признак достоверности. Всего **24 канала: 21 модель физического измерения и 3 вычисляемых канала**. Это не 24 отдельных реальных прибора.

## Состав каналов

| Каналы | Что показывают | Частота при 120 км/ч |
|---|---|---:|
| IMU1, IMU2 | По 3 удельных силы и 3 угловых скорости | 200 Гц |
| GNSS1, GNSS2 | Три координаты антенны | 20 Гц |
| BARO1, BARO2 | Атмосферное давление | 25 Гц |
| MAG1, MAG2 | Три компоненты магнитного поля в корпусе | 50 Гц |
| LIDAR_DOWN, LIDAR_FRONT | Дальность до крон и вперёд по лучу | 50 Гц |
| RADAR_ALT | Высота над землёй | 50 Гц |
| RPM | Обороты двигателя | 50 Гц |
| PWR | Потребная мощность, напряжение, ток батареи | 10 Гц |
| ADC_BATT, VOLTAGE_BUS | Код АЦП и напряжение шины | 10 Гц |
| CURRENT_MOTOR | Ток сервоприводов | 50 Гц |
| FUEL_FLOW | Модельный расход топлива | 10 Гц |
| AIRSPEED, VIBRO | Воздушная скорость; вибрация | 20; 100 Гц |
| TEMP_BATT, TEMP_IMU | Температуры батареи и IMU | 1 Гц |
| SOC_EST, GNSS_VEL, BARO_ALT | Заряд, скорость по GNSS, барометрическая высота | 1; 20; 25 Гц |

Для GNSS требуется не меньше `ceil(V/2)` Гц, для лидаров и радиовысотомера — `ceil(V/0,75)` Гц. Сохраняется максимум этого значения и базовой частоты. IMU задаётся в миссии, минимум 100 Гц. Это принятые требования к пространственному шагу измерений, не паспортные ограничения приборов.

## Где расположены датчики

Начало координат — центр масс аппарата. В таблице тройки даны **в сантиметрах** в порядке **X, Y, Z**. Положительный X направлен к носу, Y — к левому борту, Z — вверх. В каждой строке координаты перечислены в том же порядке, что и каналы. Это компоновка учебной модели. Для подтверждения точек монтажа на реальном ВТ-440 потребовались бы конструкторские данные и испытания.

| Канал | Координаты (X, Y, Z), см | Место и связь с показанием |
|---|---|---|
| IMU1 / IMU2 | (0, 0, 0) / (10, 0, 0) | Основной блок в центре масс, второй на 10 см ближе к носу. При повороте корпуса акселерометр второго блока дополнительно чувствует ускорение из-за смещения. |
| GNSS1 / GNSS2 | (15, 0, 30) / (-15, 0, 30) | Антенны в верхней части модели, на продольной оси, одна впереди центра масс, другая позади. Программа рассчитывает положение каждой антенны с учётом разворота корпуса. Затенение сигнала корпусом в модели отсутствует. |
| BARO1 / BARO2 | (5, 5, 10) / (-5, -5, 10) | Точки измерения давления выше центра масс, первая впереди слева, вторая сзади справа. Давление зависит от абсолютной высоты каждой точки. Обдув приёмников давления винтом в расчёт не входит. |
| MAG1 / MAG2 | (0, 20, 0) / (0, -20, 0) | По левому и правому бортам. Оба канала показывают магнитное поле в осях корпуса. В модели поле однородно, поэтому разнос сам по себе не меняет показания. Помехи от бортовой проводки не рассчитываются. |
| LIDAR_DOWN | (0, 0, -25) | Под центром масс, луч направлен вниз относительно корпуса. Модель оценивает дальность от этой точки до верхушек деревьев с поправкой на наклон. |
| RADAR_ALT | (0, 0, -30) | Под центром масс, на 5 см ниже нижнего лидара. Направлен вниз и измеряет расстояние до грунта. |
| LIDAR_FRONT | (30, 0, 0) | Впереди центра масс на продольной оси, луч направлен по оси X к носу. Отсюда программа отсчитывает расстояние до пересечения с поверхностью или препятствием. |
| AIRSPEED | (40, 0, 0) | Передняя точка на продольной оси, на 10 см впереди переднего лидара. Канал показывает скорость аппарата относительно воздуха. Местное течение около корпуса отдельно не рассчитывается. |
| RPM / FUEL_FLOW | (0, 0, 15) / (0, 0, 15) | Одна условная точка для двух каналов двигателя. RPM относится к вращению вала, FUEL_FLOW — к расходу в топливной линии. Показания зависят от расчётной мощности. Совпадение координат не означает общий прибор. |
| PWR / ADC_BATT / VOLTAGE_BUS | (0, 0, 5) / (2, 0, 5) / (0, 0, 8) | Центральная зона электрооборудования. PWR объединяет расчётную мощность вала с напряжением и током батареи. ADC_BATT даёт цифровой отсчёт напряжения батареи, VOLTAGE_BUS — напряжение бортовой шины. |
| CURRENT_MOTOR | (0, 0, 10) | Центральная зона, ветвь питания сервоприводов. Канал показывает ток этих приводов. |
| TEMP_BATT / TEMP_IMU | (2, 2, 5) / (2, 0, 0) | Первый канал привязан к батарее, второй расположен на 2 см впереди центра IMU1. Каждый показывает температуру своего узла. Распространение тепла между точками корпуса программа не рассчитывает. |
| VIBRO | (5, 0, 0) | На продольной оси, на 5 см впереди центра масс, рядом с IMU1. Канал характеризует вибрацию в зоне инерциального блока. Вибрация задаётся модельным сигналом без расчёта колебаний конструкции. |

**Три вычисляемых канала** отдельного места установки не требуют. GNSS_VEL использует координаты первой антенны GNSS1, BARO_ALT — давление первого барометра BARO1, SOC_EST — ток из канала PWR.

## Как формируются измерения

Истинное состояние интерполируется на собственную шкалу времени канала. Затем учитываются положение датчика, ориентация, шум и постоянное смещение. Для повторяемости каждый канал получает отдельный генератор из `seed=42` и своего индекса.

Мир **ENU**: X — восток, Y — север, Z — вверх. Корпус **FLU**: X — вперёд, Y — влево, Z — вверх. Матрица `R` переводит векторы из корпуса в мир. Плечо `r` — координаты датчика относительно центра масс; например, GNSS1 стоит в (0,15; 0; 0,30) м.

Акселерометр измеряет **удельную силу**, а не готовое мировое ускорение:

`fкорп=Rᵀ(aмир−g)+α×r+ω×(ω×r)`.

Два последних слагаемых учитывают ускорение удалённого от центра датчика при вращении. Гироскоп даёт угловую скорость корпуса. GNSS измеряет `pантенны=pцентра+Rr` с шумом. Магнитометр получает мировое поле после поворота в корпус. Нижний лидар видит кроны, радиовысотомер — землю; передний лидар проходит по лучу с шагом 2,5 м.

Вычисляемые каналы используют другие измерения: `BARO_ALT` — давление BARO1, `GNSS_VEL` — разность координат GNSS1, `SOC_EST` — интеграл тока PWR. Скорость GNSS здесь не доплеровская.

## Отказ и проверка

С 300 до 360 с у обеих GNSS-антенн записываются **NaN и качество 1**. Ноль координат не подставляется. Качество 0 — достоверный отсчёт; 2 — выход дальномера за диапазон. Резервные приборы моделируются, автоматическое переключение не реализовано.

Тесты проверяют 24 канала, размерности, расписания, конечность достоверных значений, различие шумов IMU, воспроизводимость, производную баровысоту и изменение частот со скоростью. `telemetry.py` сохраняет каналы и поток STATE: всего 25 потоков, базовый поток данных **31 920 байт/с**.

## Почему выбраны именно эти группы датчиков

Состав сохраняет 24 позиции принятого в проекте перечня исходных материалов. **Число 24 не получено оптимизацией количества приборов.** Обоснование ниже объясняет назначение групп в учебной модели; конкретные марки, стоимость и реальная бортовая комплектация не подбирались.

| Группа | Зачем включена и что реально используется |
|---|---|
| IMU1/IMU2 | Ускорения и вращение нужны для инерциальной навигации. Второй IMU позволяет сравнивать независимые модельные погрешности; навигация использует IMU1 |
| GNSS1/GNSS2 | Внешние координаты ограничивают инерциальный дрейф. В навигации используется GNSS1; GNSS2 записывается, переключение не реализовано |
| BARO1/BARO2 | Дополнительный способ оценки высоты по давлению; BARO_ALT вычисляется из BARO1. В текущий навигационный фильтр барометр не включён |
| MAG1/MAG2 | Модель измерения магнитного поля для задачи определения направления; коррекция ориентации по магнитометрам сейчас не выполняется |
| LIDAR_DOWN/RADAR_ALT | Различаются наблюдаемой поверхностью: кроны и земля. Это позволяет сопоставить высоту над лесом с высотой над грунтом |
| LIDAR_FRONT | Демонстрирует дальность вперёд до синтетической поверхности и физических препятствий; автопилот по его данным не управляется |
| RPM, FUEL_FLOW, AIRSPEED, VIBRO | Диагностика двигателя, ресурса и условий движения; связь потребной мощности с расходом и воздушной скоростью |
| PWR, ADC_BATT, VOLTAGE_BUS, CURRENT_MOTOR | Разные представления электрического состояния: мощность/напряжение/ток, код АЦП, напряжение шины и ток сервоприводов |
| TEMP_BATT/TEMP_IMU | Демонстрация температурного состояния двух узлов |
| SOC_EST, GNSS_VEL, BARO_ALT | Производные оценки: используют уже существующие измерения и не добавляют три физических прибора |

Парные IMU/GNSS/BARO/MAG показывают структуру с резервными каналами. Это **не доказательство реализованной отказоустойчивости**: переключения нет, а отказ GNSS в нашем сценарии общий для обеих антенн. Часть каналов служит диагностике и записи, часть — входам алгоритмов; наличие канала не означает его использование в фильтре навигации.

## Почему такие частоты, погрешности и координаты

IMU 200 Гц даёт шаг интегрирования 5 мс. GNSS 20 Гц даёт поправку через 50 мс и перемещение около 1,67 м при 120 км/ч. Дальномер 50 Гц соответствует шагу около 0,67 м. Формула `f≥V/Δs` связывает частоту с выбранной пространственной детализацией: Δs=2 м для GNSS и 0,75 м для дальномеров. Температура и SOC выводятся на 1 Гц как медленно меняющиеся величины; вибрация — на 100 Гц для заданной в модели составляющей 18 Гц. Эти частоты обеспечивают принятую демонстрацию, но не обосновывают полосу реальных приборов и антиалиасинговые фильтры.

Шум IMU: σ ускорения 0,02 м/с², σ угловой скорости 0,0001 рад/с; шум GNSS: σ=1,2 м **по каждой координате**, не радиус гарантированной ошибки. Постоянные смещения IMU заданы отдельно. Параметры нужны для воспроизводимой демонстрации ошибок и дрейфа; по паспорту конкретного датчика или эксперименту они не идентифицированы. Другие шумы также заданы в `sensors.py`, например 2 Па для барометра и 0,05 м для нижнего лидара.

Координаты каналов сохранены в конфигурации относительно центра масс. Расположение IMU1 в центре упрощает опорную модель, смещение IMU2 и GNSS показывает влияние плеча. Это функциональное объяснение принятой компоновки; реальные вибрационные, магнитные и монтажные ограничения не проверялись.

## Почему 24 канала, а графиков датчиков только четыре

**24 — число рассчитываемых каналов, четыре — число выбранных панелей измерений.** При `--record` сохраняются все 24 канала с полными размерностями плюс поток STATE. Например, IMU1 содержит шесть величин, но его панель показывает только первую — удельную силу по X, подписанную в интерфейсе «Удельная сила X корпуса».

| Панель | Почему показана |
|---|---|
| IMU1, компонента X | Видна динамика движения и измерительный шум |
| FUEL_FLOW | Видна связь режима полёта с расходом топлива |
| LIDAR_DOWN | Видны изменения расстояния до крон при рельефе и подъёмах |
| TEMP_BATT | Показан медленно меняющийся параметр состояния оборудования |

Эти четыре примера представляют движение, топливо, расстояние и температуру и помещаются в общем окне промежуточной версии. Переключатель сигналов ранее убран по требованию команды. Это не полный экран мониторинга борта: в следующем приложении состав представления может быть расширен.

Карта, AGL, скорость, остаток топлива и мощность дополнительно показывают **расчётное состояние**. Они не равнозначны отдельным датчикам: например, AGL на основном графике не вычисляется из LIDAR_DOWN. Полный перечень каналов и их состояние проверяются в JSON, прореженные примеры — в `sensor_samples.csv`, полные значения — в `telemetry/*.bin` после `--record`.

Графики также прореживаются: в новом расчёте быстрые каналы отображаются примерно на 5 отсчётах/с, а в `replay` используются CSV-примеры через 5 с. Модель IMU при этом остаётся 200 Гц. Такая картинка показывает общую динамику, но не заменяет анализ полного спектра и быстрых сигналов по сырой записи.

## Что сказать на защите

«Я отвечаю за модели измерений. Из истинного движения формируются 24 канала с собственными частотами, плечами установки и погрешностями. Пропадание GNSS отмечается явно. Навигация затем работает по измерениям IMU1 и GNSS1, а не получает истинную траекторию для коррекции».

Это синтетические сигналы. При невыполнимом плане энергетические каналы продолжают показывать расчётную потребность маршрута; они не являются телеметрией реально работающего двигателя.
