# Серёга — тестирование и формирование отчётов

## Что сделано и где смотреть

Тесты находятся в [`tests/`](../../tests), повторяемые эксперименты — [`scripts/run_experiments.py`](../../scripts/run_experiments.py), проверка топлива — [`scripts/check_fuel.py`](../../scripts/check_fuel.py). `dtwin/simulation.py` формирует проверки сценария, JSON и CSV; `dtwin/plots.py` строит графики; `scripts/build_report.py` собирает Word и заметки из результатов. GitHub Actions запускает проверки при обновлении репозитория на Python 3.11 и 3.12.

## Что именно проверяется

| Часть | Содержание проверки |
|---|---|
| Конфигурация | Положительные параметры, конечные числа, масса, КПД, плотность, объём бака |
| Траектория | Семь препятствий, точные добавки, 60→90 м AGL, абсолютная высота, сходимость сетки |
| Геометрия и движение | Запретная зона, мост, кроны, крен, ускорение, скорость набора |
| Энергия | Баланс энергии и потребности, масса, резерв 3%, подбор заправки, неотрицательный бак |
| Датчики | 24 канала, частоты, размерности, GNSS-отказ, шумы и повторяемость |
| Навигация | Покой без шума, равномерное движение без GNSS, ошибки и восстановление коррекции |
| Запись | Чтение обратно, точный размер, выявление оборванного файла |
| Интерфейс | Все четыре сигнала сразу, синхронная перемотка, отсутствующие данные и размещение текста |

В текущей проверке пройдены **39 тестов** и **16 проверок команд запуска**. Фактически выполненные проверки приведены в [протоколе](../verification.md), полный вывод — `results/test_results.txt`, команды — `results/program_checks.json`.

## Как устроены эксперименты

`run_experiments.py` запускает четыре сценария с общей конфигурацией и фиксированными шумами. `nominal` — без отказа GNSS; `gnss_dropout` — потеря сигнала на 5–6-й минуте; `low_fuel` — заправка 1 кг; `strong_wind` — ветер (−18; 8; 0) м/с. Полная навигация считается в двух первых сценариях. В контрольном сценарии также создаются 25 двоичных потоков.

**Успешный тест и успешная миссия различаются.** Тест дефицита проходит, когда программа обнаруживает нехватку. Штатный и GNSS-сценарий должны пройти проверки миссии; `low_fuel` — получить отказ по резерву, `strong_wind` при 10 кг — по мощности. Код 2 в этих запусках ожидаем и подтверждает работу проверок.

Результаты сохраняются в `results/reference/`, `nominal/`, `low_fuel/`, `strong_wind/`; сводка — `results/experiments.csv`. JSON содержит параметры, показатели, проверки и общий `passed`. Графики строятся из тех же рассчитанных массивов. Бюджет памяти сравнивается с действительными размерами записи, не только с приближённой формулой «скорость потока × время».

## Как повторить и подготовить материалы

```bash
python -m unittest discover -s tests -v
python scripts/verify_program.py
python scripts/check_fuel.py
python scripts/run_experiments.py
python -m dtwin replay results/reference
```

[`docs/requirements.md`](../requirements.md) связывает требования с модулями и проверками. `build_report.py` читает готовые JSON и графики и через `python-docx` создаёт Word; сначала необходимо воспроизвести результаты. Word и презентация в текущем обновлении сохранены от предыдущей версии: актуальные числа берутся из `results/` и персональных памяток. Их пересборка запланирована отдельно.

Важно, что программа правильно обнаруживает дефицит топлива и превышение мощности. Результаты и графики воспроизводятся скриптом, а параметры и проверки сохраняются вместе с ними».

Тестирование подтверждает работу реализованного алгоритма. Оно не заменяет проверку аэродинамической модели по натурным данным. Интерфейс проверяется также без экрана; отдельная проверка окна на компьютере пользователя остаётся платформенной проверкой.
