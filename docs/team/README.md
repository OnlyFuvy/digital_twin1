## Как части связаны

1. `config/mission.json` задаёт миссию и параметры, `config/sensors.json` — измерительные каналы.
2. Траектория и рельеф дают истинные координаты, скорость, ускорение и ориентацию по времени.
3. Энергетика добавляет мощность, топливо, массу и состояние батареи.
4. Датчики превращают истинное состояние в измерения с шумами и отказами.
5. Навигация оценивает движение по IMU и GNSS; истинная траектория нужна для подсчёта ошибки.
6. `simulation.py` собирает результаты, выполняет проверки, сохраняет JSON/CSV и телеметрию. Графики и проигрыватель показывают эти данные.

Общие соглашения: единицы СИ; мир ENU — X на восток, Y на север, Z вверх; корпус FLU — X вперёд, Y влево, Z вверх. Действующая программа находится в `dtwin/`; `src/model/` — исторические наработки.

## Как читать обоснование параметров

В каждой памятке добавлены основания выбора параметров своей части и связь с датчиками/отображением. Различаются:

| Основание | Примеры | Что можно утверждать |
|---|---|---|
| Требования и исходные материалы принятой постановки | Семь препятствий, резерв 3%, перечень каналов, выбранная конфигурация ВТ-440 | Модель реализует зафиксированную постановку; неоднозначности перечислены в допущениях |
| Выбор учебного сценария и численного метода | База 20 км, сетка 2 м, ветер, минутный отказ GNSS, seed | Настройки делают эксперимент повторяемым и позволяют проверить выбранные эффекты |
| Оценочные параметры без натурной идентификации | Сухая масса, коэффициенты мощности/расхода, шумы, настройки фильтра | Это допущения модели; выполнение тестов не подтверждает заводские характеристики |

Подробные значения находятся в `config/mission.json`, `config/sensors.json`; часть коэффициентов задана непосредственно в `route.py`, `sensors.py`, `navigation.py`. Объяснение цели настройки не равнозначно доказательству её оптимальности. Перечень допущений: [assumptions.md](../assumptions.md).

## Почему 24 канала не равны 24 графикам

Модель формирует **24 канала: 21 модель физического измерения и 3 производные оценки**. Один канал может иметь несколько компонент, например IMU — шесть. При полной записи сохраняются все каналы и STATE. Навигационный фильтр использует IMU1/GNSS1, остальные каналы нужны для диагностической модели и записи.

Основное окно содержит **четыре панели датчиков**: IMU1 по X, FUEL_FLOW, LIDAR_DOWN, TEMP_BATT. Они представляют движение, расход, расстояние и температуру и выбраны для демонстрации в одном окне. Дополнительные карта, высота, скорость, топливо и мощность берутся из расчётного состояния. Прореживание изображения не уменьшает частоту модели. Пояснения по выбору групп, резервированию, частотам, шумам и доступу к полным данным — в [памятке Ильи](ilya_sensors.md).

## Общий запуск

```bash
python -m pip install -r requirements.txt
python -m dtwin replay results/reference
python -m unittest discover -s tests -v
python scripts/run_experiments.py
```

Текущая заправка — **10 кг**. Обоснование и ограничения: [перепроверка топлива](../fuel_review.md). Word и презентация пока относятся к предыдущей версии; для актуальных чисел используются `results/` и эти памятки.
